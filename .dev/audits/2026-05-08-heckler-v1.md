## 4. Cold-read log (Phase 0 — pinned)

Findings from code + §2 + tests, minimized narrative priming:

1. **`pipeline._run_reaction_worker`**: When `reactor.react` returns `result is None`, code does `assert discard_reason is not None`. The amended §2 contract implies the third tuple element is always set for failure paths; if that invariant were ever violated, the **worker thread would raise `AssertionError`**, bypassing the structured `HeckleEvent` path. Severity guess: **minor** (defensive programming vs. contract breach).

2. **`reactor._JSON_OBJECT_RE`**: Shallow `\{[^}]+\}` extraction cannot match JSON objects containing nested `}` in values. Failure mode: rare LLM outputs could fail regex fallback. Severity guess: **minor / observation** (known LLM fragility; tests cover simple preamble case).

3. **`HecklerLogger._serialize`**: Uses `dataclasses.asdict` + `_coerce_json` (not the `models.serialize_heckle_event` helper). Behavior still aligns with §2 intent (enums as values, strip `audio_chunk`). Severity guess: **observation** (duplicate serialization paths).

4. **Packaging**: `pyproject.toml` contains `[tool.setuptools.packages.find]` with `include = ["heckler*"]` — matches T10 / §2 intent on inspection.

5. **`Reactor.react`**: Returns a **3-tuple** with `Optional[DiscardReason]` as documented in plan §2 (T10 amendment); tests assert `DiscardReason.LLM_ERROR` vs `SCORE_GATE` distinctly.
