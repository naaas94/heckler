## §1 Task statement

Add a **transcribe-only mode** to heckler: a standalone pipeline path that uses `AudioCapture` + `Transcriber` (Whisper) without loading the Reactor (LLM), Speaker (Kokoro TTS), or any gates (density, score, pacing). Audio input is continuously transcribed and persisted to SQLite (session + chunks) with optional incremental markdown export. A new `--mode transcribe` CLI flag activates the mode (amending the prior `--list-devices`-only CLI contract). VAD timing defaults are overridden for longer-form speech in transcribe mode. Session lifecycle (start/stop/naming) is managed at the pipeline level.

**Non-goals:**

- PyQt6 GUI integration (separate follow-on plan).
- Speaker diarization / `pyannote.audio` integration.
- Raw audio chunk archival to disk.
- Streaming/partial transcription (Whisper streaming); chunk-based only.
- Changes to `HeckleEvent` schema, `event_store.py` DDL, or `SCHEMA_VERSION`.
- Intentional removal or disabling of persona-mode features. **Co-landing:** other plans may touch the same files (`pipeline.py`, `config.py`, `reactor.py`); the behavioral contract is **regression-tested persona behavior** (`tests/test_pipeline.py` and related), not a freeze on line-level diffs (audit **F3**).
- Modifications to `Transcriber.run` (legacy/test-only method).

## Target markdown format

From the design document, the exported markdown should look like:

```markdown
# session-name — 2026-05-16

[00:00:12] So tell me about your experience with...

[00:01:04] I've been working in distributed systems for about five years now...

[00:02:30] The main challenge was keeping consistency across regions without...
```

- Heading: `# {session_name} — {date}` (date from `session.started_at`)
- Each chunk: `[{relative_timestamp}] {chunk_text}` with a blank line between chunks
- Relative timestamps are computed from `session.started_at` to `chunk.timestamp_iso`
- File is written atomically (write all content, not append), but the function should be callable at any point during a session (it reads current chunks from DB and writes the full file)

## Implementation guidance

`export_session_markdown` receives a `conn` and `session_id`; it:
1. Calls `get_session(conn, session_id)` to get the session metadata
2. Calls `get_chunks(conn, session_id)` to get all chunks ordered by `sequence_num`
3. Computes relative timestamps from `session.started_at` ISO to each `chunk.timestamp_iso`
4. Formats and writes to `output_path`
5. Creates parent directories of `output_path` if needed

Tests should:
- Insert a session + multiple chunks, export, read the file, verify format
- Test empty session (just header, no chunks)
- Test that parent directories are created
