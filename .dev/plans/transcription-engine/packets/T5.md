## §1 Task statement

Add a **transcribe-only mode** to heckler: a standalone pipeline path that uses `AudioCapture` + `Transcriber` (Whisper) without loading the Reactor (LLM), Speaker (Kokoro TTS), or any gates (density, score, pacing). Audio input is continuously transcribed and persisted to SQLite (session + chunks) with optional incremental markdown export. A new `--mode transcribe` CLI flag activates the mode (amending the prior `--list-devices`-only CLI contract). VAD timing defaults are overridden for longer-form speech in transcribe mode. Session lifecycle (start/stop/naming) is managed at the pipeline level.

**Non-goals:**

- PyQt6 GUI integration (separate follow-on plan).
- Speaker diarization / `pyannote.audio` integration.
- Raw audio chunk archival to disk.
- Streaming/partial transcription (Whisper streaming); chunk-based only.
- Changes to `HeckleEvent` schema, `event_store.py` DDL, or `SCHEMA_VERSION`.
- Intentional removal or disabling of persona-mode features. **Co-landing:** other plans may touch the same files (`pipeline.py`, `config.py`, `reactor.py`); the behavioral contract is **regression-tested persona behavior** (`tests/test_pipeline.py` and related), not a freeze on line-level diffs (audit **F3**).
- Modifications to `Transcriber.run` (legacy/test-only method).

## Tests to write

### 1. `test_run_transcribe_worker_persists_chunks`

- Create an `audio_queue` with 2 `AudioChunk` items + sentinel `None`
- Mock `transcriber.transcribe` to return known text
- Use in-memory SQLite with `init_transcript_schema` + `create_session`
- Call `_run_transcribe_worker` directly
- Assert `insert_chunk` was called twice (or query the DB directly)
- Verify `sequence_num` increments (1, 2)
- Verify `chunk_text` matches transcriber output

### 2. `test_run_transcribe_worker_skips_empty_transcripts`

- Feed one chunk where transcriber returns `"   "` (whitespace only) + sentinel
- Assert no chunks inserted

### 3. `test_run_transcribe_worker_sentinel_shutdown`

- Feed only sentinel `None`
- Assert worker returns without error

### 4. `test_main_transcribe_mode_does_not_load_speaker_or_reactor`

- Mock `load_config` to return `HecklerConfig(mode="persona")` (default — mode comes from CLI arg)
- Mock `Transcriber`, `AudioCapture`, `transcript_store` functions
- Mock `Speaker` and `Reactor` constructors to track calls
- Mock `time.sleep` to raise `KeyboardInterrupt`
- Call `main(["--mode", "transcribe"])`
- Assert `Speaker` and `Reactor` constructors were NOT called
- Assert `Transcriber` constructor WAS called

### 5. `test_main_transcribe_mode_creates_and_closes_session`

- Similar setup to test 4
- Assert `create_session` was called with a session_id and name
- Assert `close_session` was called on shutdown

### 6. `test_main_session_name_forwarded`

- Call `main(["--mode", "transcribe", "--session-name", "my-meeting"])`
- Assert `create_session` was called with `name="my-meeting"`

### 7. `test_main_persona_mode_still_loads_speaker_and_reactor` (regression)

- Call `main([])` or `main(["--mode", "persona"])` with existing mock setup
- Assert `Speaker` and `Reactor` constructors WERE called
- This is a regression test ensuring persona mode is unchanged

### 8. `test_list_devices_still_works` (regression)

- Existing test `test_list_devices_short_circuits` should continue to pass
- Optionally add `test_list_devices_with_mode_flag` to verify `--list-devices` still short-circuits even if `--mode` is also provided (argparse behavior)
