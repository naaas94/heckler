# T15 — LiteLLM observability scaffold + SQLite correlation at `react`

## Chosen approach

- **Single instrumentation surface:** Only **`litellm.completion`** (inside **`Reactor.react`**) gets extra behavior — **no** global **`litellm.success_callback`** mutation and **no** second wrapper around the pipeline (avoids duplicate Langfuse/LangSmith roots per §5 couplings).
- **Hosted tracing (env-only activation):** When **Langfuse** keys (**`LANGFUSE_PUBLIC_KEY`** + **`LANGFUSE_SECRET_KEY`**) or **LangSmith-style** tracing (**`LANGCHAIN_TRACING_V2`** / **`LANGSMITH_TRACING`** plus **`LANGCHAIN_API_KEY`** / **`LANGSMITH_API_KEY`**) are present, **`react`** passes LiteLLM **`metadata`** (`generation_name`: **`heckler.react`**, **`tags`**) so callbacks/logging integrations that operators enable via LiteLLM ≥1.40 receive tagged generations **without** importing optional Langfuse/LangSmith SDKs in heckler.
- **SQLite correlation:** After a successful **`completion`** return (no exception), **`heckler.tracing_context`** is populated from **primitive** fields on the response object (**`id`** → **`completion_id`**, **`model`**, **`system_fingerprint`**, plus **`_hidden_params`** **`litellm_call_id`** / **`model_id`** when dict-valued). Non-primitive attribute defaults (e.g. **`MagicMock`**) are ignored so tests and mocks cannot poison persisted **`correlation_json`**.

## Alternatives rejected

- **Register Langfuse via `litellm.success_callback = ["langfuse"]` in `react`:** Rejected — mutates process-global LiteLLM state, risks duplicate callbacks with operator/config setups, and can import **`langfuse`** at runtime (hard dependency / startup failure) contrary to “scaffold no-ops when tooling absent.”
- **OpenTelemetry span wrapping `react`:** Rejected — second root tracing layer outside **`litellm.completion`** (duplicate-span risk); orchestrator kill criterion.

## Assumptions made

- Operators who want Langfuse exports install **`langfuse`** (or use LiteLLM proxy/docs patterns) and configure LiteLLM env/callbacks per upstream docs; heckler only supplies **call-site metadata** and **response-derived correlation** for local SQLite joins.
- **`litellm.completion`** **`metadata`** shape remains supported across LiteLLM 1.40.x (see **`pyproject.toml`** pin); if LiteLLM renames filter keys, adjust **`_litellm_observability_completion_kwargs`** only.

## Items deferred

- **Pin-specific Langfuse/LangSmith attribute keys** beyond **`generation_name`** / **`tags`** (user id, session id): deferred until pipeline exposes stable user/session identifiers worth passing into LiteLLM.
- **Automated verification against a live Langfuse project:** deferred — tests mock **`litellm.completion`** (no network).
