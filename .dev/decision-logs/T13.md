# T13 — Config: retire `log_dir`, SQLite database path + env

## Chosen approach

- **`HecklerConfig.log_dir` removed**; persistence root for events is expressed as **`sqlite_database_path: str`** with default **`"logs/heckler.db"`**, preserving the existing **`logs/`** artifact convention while anchoring the DB file explicitly.
- **`load_config()`** reads **`HECKLER_DATABASE_PATH`**: value is **stripped**; only **non-empty** strings override the default (same hygiene as **`HECKLER_LLM_MODEL`**), so whitespace-only env does not produce an invalid path.
- **`HecklerLogger.__init__`** (minimal T2 wiring ahead of T3) resolves **`Path(sqlite_database_path).parent`**, creates that directory, and keeps interim JSONL files in that parent — behavior equivalent to the old `{log_dir}/heckler_*.jsonl` layout when the DB path is **`logs/heckler.db`**.

## Alternatives rejected

- **Keeping `log_dir` alongside `sqlite_database_path` for one release:** Rejected — §2 requires removing `log_dir` as the canonical persistence key; dual fields invite drift and ambiguous “which wins” semantics.
- **Default DB path outside `logs/` (e.g. cwd-only `heckler.db`):** Rejected — breaks operator expectations and the plan’s “historical `logs/` directory convention” note.

## Assumptions made

- **`HECKLER_DATABASE_PATH`** may be absolute or relative; relative paths resolve against the process cwd when SQLite opens them (T3), matching typical dev and deployment usage.
- **README / `.env.example`** documentation of the new env var can trail this subtask (**T5** per packet risks); **T13** records the migration so `log_dir` is not an undocumented silent removal.

## Items deferred

- **SQLite persistence and correlation columns** in **`HecklerLogger.log_event`**: owned by **T1** / **T3**; logger still writes JSONL under the DB parent until then.
- **README / CHANGELOG user-facing migration notes**: deferred to **T5** unless a follow-up packet narrows scope.
