# Decision log — T7 (Reactor)

## Chosen approach

- Implemented `Reactor` with synchronous `Anthropic(api_key=...).messages.create()` (no streaming, no async), loading `prompts/system.md` and `prompts/examples.json` from the repository root resolved via `Path(__file__).resolve().parent.parent`.
- User prompt follows the packet template with `N = config.context_window_size`, static pre-rendered `examples_block` (Input/Response lines per example, blank-line separated).
- `_parse_response` uses `json.loads` first, then regex `re.compile(r"\{[^}]+\}")` on the full raw string when direct parse fails or returns a non-dict; validates `comment`, `score` ∈ [0, 1], and `CommentType`; builds `ReactorResult` including verbatim `raw_response`.
- Score gate in `react`: return `(None, latency)` when `parsed.score < config.score_threshold` (equality passes).

## Alternatives rejected

- **Streaming responses:** Packet latency notes rule out streaming; full response with `max_tokens=150` is simpler and matches the seed contract.
- **Async Anthropic client:** Packet requires blocking calls because the reactor is intended to run in a dedicated thread elsewhere.

## Assumptions made

- Prompt paths remain `prompts/` at repository root next to the `heckler` package (same layout as tests and `Path(__file__)` resolution).
- Anthropic SDK continues to expose sync `messages.create` returning a message whose `.content` blocks expose `.type` and `.text` (handled defensively for dict-shaped blocks).

## Items deferred

- **`pip install -e .` / setuptools discovery:** Adding top-level `prompts/` causes setuptools “multiple top-level packages” (`heckler`, `prompts`) unless `pyproject.toml` restricts discovery (not in T7 files-to-touch). Follow-up: configure `[tool.setuptools.packages.find]` `include = ["heckler*"]` or equivalent in a packaging-focused task.
