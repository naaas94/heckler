# Decision log — T9 (Pipeline + README)

## Chosen approach

- Implemented `heckler/pipeline.py` with seed §4.9 ordering: `load_config()` → `HecklerLogger` → `Transcriber` (CUDA Whisper) → `Speaker` (Kokoro) → `Reactor` (Anthropic) → lightweight `ContextBuffer` / `PacingGate` → queues → `AudioCapture(..., speaker.is_playing)` → worker threads → `capture.start()`, stdout banners with wall-clock timings, and `KeyboardInterrupt` shutdown that stops capture, sends `None` sentinels through both queues, and joins workers.
- Transcription thread drains `audio_queue`, transcribes, applies `passes_gate`, uses `_put_drop_oldest` into `reaction_queue`, and optionally logs density failures when `log_density_failures` is true.
- Reaction thread snapshots context, calls `_react_with_discard` (wrapper around `Reactor.react`), evaluates `PacingGate`, logs every path via `HecklerLogger`, calls `_execute_spoken_reply` so `record_output()` happens immediately before `speaker.speak()`, catches `SpeakerError` without crashing the thread, and pushes transcripts into `ContextBuffer` after handling.
- `Reactor.react` returns `None` for API failures, parse failures, and score-gate failures indistinguishably; pipeline wraps `reactor._client.messages.create` once to capture API success/failure and raw text, then disambiguates `DiscardReason.LLM_ERROR` vs `DiscardReason.SCORE_GATE` by reusing `Reactor._parse_response` on the captured body—no signature change in `reactor.py`.

## Alternatives rejected

- **Changing `Reactor.react` to return an explicit discard reason:** Matches the error-envelope table cleanly but violates this packet’s `heckler/reactor.py`-absent file list and the executor “no interface drift elsewhere” rule.
- **Treating every `None` from `react` as `SCORE_GATE`:** Would mis-label API and JSON parse failures and contradict §2.

## Assumptions made

- Anthropic `messages.create` is invoked exactly once per `react` call and `_extract_text_content` remains sufficient to reconstruct the payload seen by `_parse_response`.
- Wrapping `client.messages.create` on the live `Anthropic` client object remains compatible with SDK upgrades (method replaced on the instance only).

## Items deferred

- **KeyboardInterrupt while workers are mid-queue:** Shutdown drops oldest queued items until a sentinel fits; extreme starvation cases could theoretically delay exit—acceptable for v1 foreground console use.

---

## Landed: post-T4 errata

- **Reactor integration:** The reaction worker calls **`reactor.react(utterance, context_block)`** and branches on the returned **`(result, llm_latency_ms, discard_reason)`** tuple. **`DiscardReason.LLM_ERROR`** vs **`SCORE_GATE`** (and parse failures surfaced as **`LLM_ERROR`**) come from **`Reactor`** itself; the pipeline does **not** wrap **`Anthropic.messages.create`** or re-parse raw bodies to disambiguate failures.
- **LLM backend:** **`Reactor`** is LiteLLM-backed (`litellm.completion`); the earlier narrative assuming a live Anthropic client and a pipeline-level **`messages.create`** wrapper described pre-migration wiring and is **not** current behavior.
- **Rest of pipeline:** Stage ordering, queue wiring, **`PacingGate`**, **`Speaker`** error handling, JSONL logging, and **`--list-devices`**-only CLI remain as in “Chosen approach” above.
