# Decision log — T7 (Reactor)

## How to read this log

**Current behavior** matches **`heckler/reactor.py`** as of the LiteLLM migration. **Historical** sections are fenced archaeology only—do not use them to infer today’s integration.

## Current behavior (shipped)

- **`Reactor`** loads **`prompts/system.md`** and **`prompts/examples.json`** from the repository root resolved via **`Path(__file__).resolve().parent.parent`**.
- **`react`** calls **`litellm.completion`** synchronously (lazy **`import litellm`** inside the method) with OpenAI-style **`messages`**: `system` carries the system prompt; `user` carries the static examples block, recent context, the current utterance transcript, and the JSON-only instruction. **`model=`** is **`config.llm_model`**; kwargs **`api_key`** / **`api_base`** come from **`_litellm_auth_params(config)`** when the corresponding **`HecklerConfig`** fields are non-empty so LiteLLM and process environment defaults can apply otherwise.
- Assistant text is taken via **`completion_assistant_text`** from an OpenAI-compatible response (**`choices[0].message.content`** as **`str`** or list-shaped content parts).
- **Failures:** any **`Exception`** from the completion call is logged at ERROR as **`LLM API call failed: %s`** (provider-agnostic) and **`react`** returns **`(None, latency_ms, DiscardReason.LLM_ERROR)`**.
- **`_parse_response`:** **`json.loads`** first, then regex **`re.compile(r"\{[^}]+\}")`** on the full raw string when direct parse fails or returns a non-dict; validates **`comment`**, **`score` ∈ [0, 1]**, and **`CommentType`**; builds **`ReactorResult`** including verbatim **`raw_response`**.
- **Score gate:** when **`parsed.score < config.score_threshold`**, **`react`** returns **`(None, latency_ms, DiscardReason.SCORE_GATE)`**; equality at the threshold passes.

## Historical — Anthropic SDK era (superseded)

> **Not current.** Before the **litellm-provider-switch** work, **`Reactor`** used the Anthropic Python SDK (**`Anthropic(...).messages.create()`**) with Anthropic **`content`** blocks; that transport was replaced by LiteLLM. Some older planning prose described the score gate as a two-value return; the public **`react`** contract on the branch that shipped into LiteLLM already used the **3-tuple** **`(Optional[ReactorResult], float, Optional[DiscardReason])`** (see **`CHANGELOG.MD`** → *litellm-provider-switch*).

## Alternatives rejected

- **Streaming responses:** Rejected for the reactor path; a single blocking completion keeps worker-thread semantics simple.
- **Async LLM client:** Rejected; **`react`** is invoked from a dedicated worker thread with blocking calls.

## Assumptions made (current)

- Prompt paths remain **`prompts/`** at repository root next to the **`heckler`** package.
- LiteLLM and provider stacks accept the **`max_tokens`** / **`temperature`** kwargs used for **`config.llm_model`**.

## Items deferred

- **Setuptools / `pip install -e .` discovery:** addressed under **`pyproject.toml`** in packaging tasks; not part of reactor logic.
