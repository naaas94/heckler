# T14 — HecklerLogger SQLite persistence + unified serialization

## Chosen approach

- **Single JSON projection:** `log_event` builds rows with `json.dumps(serialize_heckle_event(event), …)` only — removed `_serialize`, `_coerce_json`, and JSONL `_path_for_date` / daily files from steady state so event bodies match **`tests/test_models.py`** / round-trip semantics.
- **Store wiring:** `HecklerLogger.__init__` calls **`open_store`** → **`init_schema`** once; each **`log_event`** uses **`insert_event_row`** under the existing **`threading.Lock`** (aligned with T12 single-connection + serialized writers).
- **Correlation:** Reads **`tracing_context.get_correlation()`** before insert; passes **`correlation_json`** (serialized dict or SQL `NULL`); **`clear_correlation()`** in a **`finally`** so reaction-thread metadata does not leak across events (including after insert failures).
- **Failures:** On insert exception, log at **ERROR** with **`exc_info=True`**, then **re-raise** (surfaces write failures like prior JSONL behavior).

## Alternatives rejected

- **Dual-write JSONL + SQLite:** Rejected — §2 steady state is SQLite-only; legacy JSONL import remains **T6** if added.
- **Deferring correlation clear to callers:** Rejected — risks stale IDs on the next `log_event`; **`finally`** keeps lifecycle localized.

## Assumptions made

- **`serialize_heckle_event`** remains the sole authority for persisted **`HeckleEvent`** JSON shape (no extra columns without model/store contract updates).
- **Correlation** values are **`dict[str, str]`** per **`tracing_context`**; non-string values are **T4**/future concern.

## Items deferred

- **Explicit `Connection.close()`** on shutdown / pipeline teardown — deferred until lifecycle ownership is centralized (process exit relies on OS teardown today).
- **WAL checkpoint / vacuum policy** — operational follow-up if DB growth matters.
