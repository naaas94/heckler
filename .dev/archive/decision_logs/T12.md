# T12 — SQLite event store + tracing context skeleton

## Chosen approach

- **Module name:** **`heckler/event_store.py`** — public API: **`open_store`**, **`init_schema`**, **`insert_event_row`**, plus documented **`SCHEMA_VERSION`** for migration hooks.
- **DDL:** Table **`events`** with **`id`** (integer PK autoincrement), **`created_at`** (UTC ISO-like text via SQLite **`strftime`**, server default), **`payload_json`** (`TEXT NOT NULL`, JSON body from **`serialize_heckle_event`** + **`json.dumps`** at call sites per §2), **`correlation_json`** (`TEXT NULL`, JSON object or null for optional LiteLLM / provider metadata). Table **`heckler_schema_version`** singleton row **`id = 1`** holds **`version`** integer (**v1 = 1**). **No audio** columns or paths.
- **WAL vs DELETE:** **`PRAGMA journal_mode=WAL`** after connect, plus **`PRAGMA synchronous=NORMAL`** (paired with WAL for acceptable durability on single-machine heckler). Busy **`timeout=30s`** on **`sqlite3.connect`**.
- **Thread model:** One shared **`sqlite3.Connection`** per process with **`check_same_thread=False`** so the reaction worker thread can write using the same handle opened on the main thread; **serialized writes** via the existing **`threading.Lock`** in **`HecklerLogger`** (T3) to avoid **`database is locked`** under concurrent mic/reaction activity. Cross-thread propagation beyond the reaction worker is **out of scope** unless §2 is amended.
- **`heckler/tracing_context.py`:** **`threading.local()`** storage for **`dict[str, str]`** correlation (**`set_correlation`**, **`get_correlation`**, **`clear_correlation`**, **`reset_correlation`**) — reaction-thread scoped; T4 sets after **`litellm.completion`**, T3 reads/clears around DB insert.

## Alternatives rejected

- **Pool of connections per thread:** Rejected for v1 — unnecessary complexity; lock + single connection matches pipeline threading and keeps stdlib-only surface.
- **DELETE journaling + aggressive synchronous:** Rejected — WAL reduces writer contention versus default rollback journal for overlapping readers/writers in one process.

## Assumptions made

- **Single machine / single process** SQLite per heckler run; no multi-writer replication.
- **Schema evolution** after v1 will bump **`SCHEMA_VERSION`** and add explicit migration steps or documented rebuild strategy.

## Items deferred

- **Automatic migration** from future schema versions: deferred until a planned DDL change lands (raise **`RuntimeError`** on version mismatch today).
- **Indexes** on **`created_at`** / extracted keys inside **`payload_json`**: deferred to analytics/eval follow-ups once query patterns exist.
