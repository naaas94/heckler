# Executor Packet — T9: Pipeline + README

## §1 Task Statement

Build HECKLER, a local reactive audio commentary loop that captures microphone input continuously, segments on silence boundaries via Silero VAD, transcribes via local faster-whisper, generates snarky commentary via Claude Haiku, applies quality and pacing gates, synthesizes speech via Kokoro TTS, and plays back through system audio. Every pipeline event is logged to JSONL regardless of outcome. The system runs as a local Python process on Windows (RTX 3060 / Ryzen 5 / 64 GB RAM) with a soft latency target of 2.5 seconds end-to-end.

**Non-goals:**

- No conversational ability — HECKLER does not respond to user intent directed at it
- No GUI or web interface — console-only with JSONL logging
- No multi-language support — English only for v1
- No cloud TTS or cloud STT — all inference is local except the LLM call
- No persistent state across sessions
- No Windows service / daemon mode — foreground console process
- No score threshold auto-calibration

### Error Envelope


| Error                 | Type                         | Produced by                 | Consumed by                 |
| --------------------- | ---------------------------- | --------------------------- | --------------------------- |
| LLM call failure      | `DiscardReason.LLM_ERROR`    | `reactor.py`                | `pipeline.py` → `logger.py` |
| LLM parse failure     | `DiscardReason.LLM_ERROR`    | `reactor.py`                | `pipeline.py` → `logger.py` |
| TTS synthesis failure | `SpeakerError(Exception)`    | `speaker.py`                | `pipeline.py` → `logger.py` |
| Score below threshold | `DiscardReason.SCORE_GATE`   | `reactor.py` returns `None` | `pipeline.py` → `logger.py` |

| Density gate rejects  | `DiscardReason.DENSITY_GATE` | evaluated in `pipeline.py`  | `logger.py`                 |


No exceptions propagate to user. Pipeline threads must not die on transient errors.

`SpeakerError` is imported from `speaker.py` (T8).

### Reference: Seed §4.9 — pipeline.py (threading model)

```
Thread 1: AudioCapture._capture_loop
    └─► audio_queue (Queue, maxsize=10)

Thread 2: TranscriptionWorker
    ├─ drains audio_queue
    ├─ calls transcriber.transcribe()
    ├─ calls semantic_gate.passes_gate()
    └─► reaction_queue (Queue, maxsize=10) if passes gate

Thread 3: ReactionWorker
    ├─ drains reaction_queue
    ├─ updates context_buffer
    ├─ calls reactor.react()
    ├─ calls pacing_gate.evaluate()
    ├─ calls speaker.speak() if all gates pass
    ├─ calls pacing_gate.record_output() before speak()
    └─► calls logger.log_event() always
```

Three threads, two queues, threading primitives only. No asyncio.

### Startup sequence (order matters — from seed §4.9)

```python
def main():
    config = load_config()
    logger = HecklerLogger(config)

    # Initialize heavy models first — fail fast before any audio starts
    transcriber = Transcriber(config)   # loads Whisper to CUDA
    speaker = Speaker(config)           # loads Kokoro
    reactor = Reactor(config)           # loads prompts, initializes Anthropic client

    reaction_queue = queue.Queue(maxsize=config.queue_maxsize)

    # Capture last — mic opens here
    capture = AudioCapture(config, audio_queue, speaker.is_playing)

    # Block on KeyboardInterrupt
    try:
        while True:
            time.sleep(0.1)
    except KeyboardInterrupt:
        capture.stop()
        # drain queues with timeout, then join threads
```

### Queue overflow policy (from seed §4.9)

If a queue reaches maxsize, producer drops oldest (not newest). Implementation: `queue.put_nowait()` in try/except `queue.Full`, then `queue.get_nowait()` + discard + retry. Do not use `block=True` with timeout.

### `log_density_failures` handling

When `config.log_density_failures` is `True`, the transcription worker must also log events that fail the density gate (construct a `HeckleEvent` with `passed_density_gate=False`, `discard_reason=DiscardReason.DENSITY_GATE`, and all downstream fields as `None`).

When `False` (default), density-gate failures are silently dropped — no log entry, no queue put.
