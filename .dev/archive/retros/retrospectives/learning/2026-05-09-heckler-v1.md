## 2. What I now understand that I didn’t before

**Explicit beats inferred at module boundaries.** The v1 pipeline worked around an ambiguous `react()` `None` by wrapping `messages.create` and re-parsing — clever, but it fought the §2 error-envelope table. Widening the return type to a **3-tuple** and pushing discard semantics into `Reactor` is not “more typing”; it is **making the failure mode part of the API** so consumers do not need private-field surgery. I will remember this as: if the log schema distinguishes cases, the **return type or event type should distinguish them too**, unless there is a deliberate, documented aggregation layer.

**Amendments change what “done” means for every downstream artifact.** T10 updated `plan.md` §2 with *Landed* notes, but architectural **decision logs** and parts of the **changelog** still narrated pre-T10 wiring at audit time (F-01, F-02; changelog timeline under T9 vs T10). I now treat **plan §2 as canonical for behavior** and decision logs as **append-only with supersession blocks** — or I accept that audits will keep flagging `decision-log-stale`. The mental model is: **amendment = patch the contract graph**, not only the diff.

**“No integration tests in v1” does not remove obligations implied by kill criteria.** T9 required proper thread joins on shutdown; the audit found **no test** driving `main()`’s `finally` join path (F-03). The lesson is not “write integration tests anyway” blindly — it is that **kill criteria written as observable system behavior need either a test, a scoped harness, or an explicit plan-level waiver**. Otherwise executors ship plausible code and CI never disagrees.

**Greenfield + orchestrator packets worked for parallelization.** Layer 1 isolation matched real dependency structure; T9 as the fan-in point correctly concentrated coordination risk. The adversarial pass’s rejected alternatives (monolith, deferred test lump, merged capture/transcriber) look **load-bearing in hindsight** — they explain why the repo stayed navigable.

**Assumption tables age when reality forks.** Plan §5.2 named Anthropic sync SDK assumptions; later LiteLLM migration shifted transport without invalidating the broader pattern (sync call in a worker thread, structured parse). I now read §5.2 as **“verify or update when the integration substrate changes”**, not as frozen prophecy.

## 3. Decisions I made and would make again

- **DAG with T9 as single integrator after parallel modules** — contained wiring bugs to one place; audit A1–A4, A6 passing on seams supports this.
- **T10-style amendment** instead of letting monkey-patch persist — restored alignment between code and §2 and removed hidden coupling to `_client`.
- **Coupling surfaces enumerated in §2** (queues, `is_playing`, `record_output` ordering, JSONL exclusions) — made Phase 4 adversarial checks tractable; I would reuse that table shape on future pipelines.
- **Formal adversarial audit after execution** — caught stale logs and a real test gap that green tests alone did not signal.

---

## 4. Decisions I made that I would change

- **Treating decision logs as fire-and-forget after T7/T9 shipped** — left “Chosen approach” sections that contradicted T10 until errata / follow-up edits. Better rule: **any task that amends §2 rows tied to a decision log path must list “refresh log(s) X” in that amendment’s DoD**, same priority as code.
- **Kill criterion “threads properly joined” without a binding test or waiver** — created an honest gap between process rhetoric and verifiability. Next time: pair each shutdown-related kill criterion with **one** minimal test strategy (mocked `main`, or documented waiver + manual checklist).
- **Relying on changelog subsections as historical timeline without a one-line “current behavior” pointer** — confused traceability (audit Phase 1 note). Either top-of-section “**Current:** …” or errata blocks in logs earlier in the chain.

Underlying error mix: **good information at plan time**, then **artifact hygiene lagged contract velocity** after T10 (and again after LiteLLM); plus **under-specified verification** for one kill criterion.

## 5. Patterns in my own thinking

- **Trusting that “architectural tier” logs would track code** when amendments landed — they don’t unless the workflow **forces** the update. That is a mild “orchestrator output is sacred” bias; the audit was right to treat stale logs as **major**.
- **Possible under-weighting of verification design** next to feature decomposition — lots of energy on packets and contracts, less on **which kill criteria are mechanically checkable** under stated CI constraints.
- **No strong sign of sunk-cost defending the monkey-patch** — T10 shows willingness to rip an expedient pattern when §2 clarity demanded it; the open loop is **follow-through on documentation**, not denial of the problem.

## 7. Single paragraph synthesis

Heckler-v1 reinforced that **contracts live in types and seams**, not in narrative: widening `react()` to carry `DiscardReason` removed a whole class of pipeline cleverness, and the formal audit was right that **amendments oblige supersession hygiene in decision logs and tests**, not just edits to `plan.md` and code. The compounding lesson is to treat **kill criteria as claims that need a verification hook or an explicit waiver** — especially for threading and shutdown — and to assume **assumption tables and logs go stale** whenever the integration layer changes unless the workflow bakes in a short update pass.
