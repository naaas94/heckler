# Executor Packet — T3: GUI Application + Packaging

---

## §1 Task statement

Build a minimal PyQt6 GUI launcher for Heckler that replaces the blocking CLI `main()` loop with a Qt event loop, exposes persona hot-swap (runtime `Reactor` replacement between utterances) and mode switching (persona ↔ transcribe) in a single window with live transcript/reaction feeds and session controls. The GUI layer is the integration surface deferred by both the persona-system and transcription-engine plans.

**Non-goals:**

- Advanced GUI features (settings panels for VAD thresholds, LLM temperature sliders, session history browser, tray icon).
- Multi-window or multi-monitor support.
- Electron, web, or any non-PyQt6 frontend.
- Changes to the LLM, TTS, or transcription backends (Reactor, Speaker, Transcriber internals unchanged).
- Mobile or cross-platform packaging.
- CLI flag changes on the existing `heckler` entry point.

## Implementation guidance

### Architecture

The GUI has three layers:

1. **`app.py`** — Entry point. Creates `QApplication`, `HecklerConfig`, `PipelineController`, `HecklerMainWindow`. Runs the Qt event loop.
2. **`main_window.py`** — Main window widget. Contains all UI elements and connects controller callbacks to Qt signals.
3. **Signal bridge** — Controller callbacks are called from worker threads. They must emit Qt signals (which are thread-safe) to update widgets on the main thread. Pattern:

```python
class SignalBridge(QObject):
    transcript_received = pyqtSignal(str)
    reaction_received = pyqtSignal(object, bool)  # ReactorResult, was_spoken
    status_received = pyqtSignal(str)
    error_received = pyqtSignal(str)
```

The `ControllerCallbacks` are wired to emit these signals:

```python
bridge = SignalBridge()
callbacks = ControllerCallbacks(
    on_transcript=bridge.transcript_received.emit,
    on_reaction=lambda result, spoken: bridge.reaction_received.emit(result, spoken),
    on_status=bridge.status_received.emit,
    on_error=bridge.error_received.emit,
)
```

Then connect signals to widget update slots on the main window.

### Widget layout

Suggested layout (executor may adjust for UX):

```
┌─────────────────────────────────────────────┐
│  [Mode: ● Persona ○ Transcribe]  [Persona ▼]│  ← toolbar / header
├─────────────────────────────────────────────┤
│                                             │
│  Live Feed (QPlainTextEdit, read-only)      │  ← transcript + reactions
│  [00:01:23] "What was said..."              │
│  > AI reaction (spoken)                     │
│                                             │
├─────────────────────────────────────────────┤
│  Status bar: "Mic open. Listening."         │  ← on_status messages
│  [Start/Stop]  [Export] (transcribe mode)   │  ← session controls
└─────────────────────────────────────────────┘
```

**Persona picker:** `QComboBox` populated by `list_personas(prompts_root)` at startup. Selection change triggers `controller.swap_persona(selected_name)`. Disabled when pipeline is not running or in transcribe mode.

**Mode toggle:** `QRadioButton` group or `QComboBox` for persona / transcribe. Change triggers `controller.switch_mode(new_mode)`.

**Live feed:** `QPlainTextEdit` (read-only). `on_transcript` appends text. `on_reaction` appends reaction with visual distinction (e.g., indented, different color, prefix `>`). Use `appendPlainText()` or `appendHtml()`.

**Start/Stop button:** Toggles `controller.start()` / `controller.stop()`. Label changes based on `controller.is_running`.

**Export button:** Visible in transcribe mode. Calls transcript export (the controller handles session lifecycle; the GUI can expose an export action that the controller provides, or call `export_session_markdown` directly after stop).

### Model loading

`load_models()` is blocking (~13s). Must not run on the Qt main thread. Options:

1. **QThread subclass:** Override `run()` to call `controller.load_models()`. Emit a signal when done.
2. **concurrent.futures.ThreadPoolExecutor:** Submit `load_models`, poll completion with QTimer.

Either approach works. Show a `QProgressDialog` or splash overlay during loading. The `on_progress` callback receives status strings like `"Loading transcription model (large-v3 / CUDA)..."` — display them in the dialog.
